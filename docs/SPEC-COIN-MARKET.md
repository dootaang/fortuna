# 환전가 거래소 (코인 시세 레버리지) 설계

> 구현됨 (2026-10-13, 9절 추천안 그대로): `packages/core/src/market`, `apps/notifier/src/oracle.ts`(시세 기록원),
> `packages/data/src/market-ops.ts`, `firestore.rules`(거래소 블록), `apps/fortuna/src/market`, `apps/fortuna/src/dealer/MarketAdmin.tsx`,
> 테스트 `packages/core/test/market.test.ts`, `packages/rules-tests/test/market.test.ts`, `e2e/market.spec.ts`. 운영은 DEALER-GUIDE의 "환전가 거래소".
>
> 구현하면서 정한 것: 청산 수수료 = 진입 수수료(무월리 밤에는 2배). 기록원은 Firebase 서비스 계정 대신 `oracles/{uid}`에 등록한 전용 익명 계정으로 규칙을 거쳐 쓴다.
> 난수는 Worker 비밀값의 HMAC에서 나오므로 엔진 상태는 공개해도 된다(`market/engine` 문서는 따로 두지 않았다). 아무도 안 볼 때 쓰기를 줄이는 절전은 두지 않았다(하루 약 5,800회로 한도 안).
> 2026-10-13 추가: **현물**(`packages/core/src/market/spot.ts`, `holdings/{pid}_{coin}`, 장부 spotBuy/spotSell, 매수 하루 20회)과
> **간부전 예고 시 그 종목 새 진입·매수 정지**(`config/market.coins.*.paused`, 해방이 틱에 반영되면 자동으로 다시 열림). 시세 시계는 Durable Object 알람(15초, 10~60초 설정 가능).
> 공정성 증명(씨앗 공개)은 아직 없다. 간부전 예고는 세기 "출렁임만"(점프 없음) 소식으로 낸다. 시뮬레이션 기대값: 5배·1시간 약 98%, 10배·30분 약 96%, 20배·15분 약 92%.

휠 광장 환전가에 거래소가 열린다. 도시의 여덟 구역과 광장마다 시세가 움직이는 "종목 코인"이 있고,
플레이어는 게임 코인을 증거금으로 걸어 그 시세에 롱(오름)이나 숏(내림)을 건다.
모자란 돈은 지배인이 빌려준다. 그게 레버리지다.

세계관에 이미 실마리가 있다. 한빛특구 편의점 파라솔 아래의 헌터들은 "전광판의 코인 시세를 멍하니 올려다본다".
그 전광판을 앱으로 옮기는 기획이다.

"FTN 롱 10배, 증거금 200코인"처럼 쓰면 헷갈리지 않는다.

### GM 전용: 빚에 묶인 FTN (끄고 켤 수 있음)

05-gm-secrets.md의 중반 단서 "빚을 다 갚은 주민이 있는 날 그의 힘이 약해진다"를 시세로 비춘다.

- FTN의 기준가는 도시 전체 플레이어 빚 총액에 비례해 움직인다. 누가 빚을 갚으면 FTN이 조용히 빠진다.
- 화면 어디에도 이유를 쓰지 않는다. "왜 누가 빚을 갚는 날마다 FTN이 떨어지지?"를 플레이어가 스스로 발견하게 둔다.
- 해방 시 FTN이 내려앉는 것도 같은 단서 "구역이 해방된 뒤 지배인의 금고 숫자가 줄어든다"의 시세판 버전이다.
- 딜러 설정에서 끄면 FTN은 평범한 지수로 움직인다.

## 3. 시세 엔진

### 모델
틱(15초)마다 종목별 로그 가격이 아래를 더해 움직인다. 모든 계수는 `config/market`에 있고 딜러가 바꿀 수 있다.

1. **공통 요인**: FTN의 움직임 × 종목 베타(0.3~0.8)
2. **고유 잡음**: σ × 시간대 배율 × 국면 배율 × 정규분포 난수
3. **복원력**: (기준가 − 현재가) 쪽으로 약하게 끌어당김. 종목마다 세기가 다르다(ORB 강함, JWN 약함)
4. **국면**: 평온 ↔ 폭풍 두 상태를 오가는 마르코프 전환. 폭풍이면 변동성 2.5배. 전광판에 "폭풍" 표시
5. **점프**: 드물게 ±5~15% 순간 이동 (종목별 확률)
6. **일정 효과**: 2절 표의 납부일, 입장료, 보름, 밤 같은 정해진 시각의 효과
7. **사건 충격**: 해방, 뉴스 같은 외부 입력. 즉시 점프 + 일정 시간 추세 + 변동성 상승

추세(드리프트)는 평균 0이다. 수수료와 이자가 없으면 롱도 숏도 기대값이 같다.
그래서 "어느 쪽이 무조건 이기는 종목"이 없고, 정해진 일정(LNH 납부일 등)을 아는 사람만 약간의 우위를 얻는다. 세계관을 읽은 보상이다.

### 기대값과 지배인 몫
| 항목 | 기본값 | 근거 |
|---|---|---|
| 개설·청산 수수료 | 명목가(증거금×배율)의 각 0.1%, 최소 1코인 | 10배면 왕복 증거금의 2% |
| 지배인 이자 | 빌린 금액(명목가 − 증거금)의 시간당 0.2%, 시작한 시간마다 | 오래 들고 있을수록 불리. 1배는 빌린 돈이 없어 이자 0 |
| 강제 청산 | 손실이 증거금의 90%에 닿으면 | 남은 10%는 지배인 몫 |
| 수익 상한 | 증거금의 10배에서 자동 익절 | 한 번에 경제가 무너지지 않게 |

목표: 15분~1시간 보유, 5~10배 기준 왕복 기대값 96~97%. 기존 `rtp.test.ts`처럼 시뮬레이션 테스트로 수치를 고정한다.

### 레버리지 한도
| | 하우스 잠김 | 하우스 개장 후 |
|---|---|---|
| FTN | 5배 | 20배 |
| 알트 | 3배 | 10배 |

하우스가 열리는 순간이 거래소에도 한 단계 오르는 순간이 된다.

## 4. 공정성과 실시간 (서버 없이)

현재 구조는 "미리 정할 수 있는 무작위"만 다룬다(봉인된 판, 배분표). 시세는 다르다.
미래 가격을 어디에든 미리 적어 두면 레버리지로 무조건 이긴다. 그래서 **미래를 아무도 모르는 상태로, 시간이 흐를 때 한 칸씩 찍는 존재**가 필요하다.

### 시세 기록원 = 기존 Cloudflare Worker
- 알림 중계용으로 이미 배포한 Worker에 **크론(1분)** 을 붙인다. 한 번 깨어나면 15초 간격으로 틱 4개를 찍고 잠든다.
- Worker는 Firestore에 전용 계정으로 로그인한다. 관리자처럼 `oracles/{uid}` 허용 목록에 등록한 계정이고, 비밀 키는 Worker secret에만 둔다.
- Worker가 쓰는 곳은 **시세 문서와 청산 표시뿐**이다. 코인(지갑·장부·금고)은 절대 건드리지 않는다. 코인 이동은 지금처럼 전부 플레이어 앱의 쓰기 + 보안 규칙 검증으로 일어난다.
- 난수 상태와 국면은 Worker만 읽을 수 있는 문서(`market/engine`)에 둔다. 플레이어는 다음 틱을 계산할 수 없다.

### 거래 검증 (보안 규칙)
- **진입**: "지금 최신 틱 번호 N, 가격 P로 산다"를 쓰면, 규칙이 시세 문서를 직접 읽어 N이 최신이고 P가 맞는지 확인한다. 그 사이 새 틱이 찍혔으면 거절되고 앱이 자동으로 다시 시도한다.
- **청산(직접)**: 같은 방식으로 최신 틱 가격에 닫는다. 수익·수수료·이자 계산을 규칙이 그대로 다시 해서 금액이 1코인이라도 다르면 거절한다.
- **강제 청산**: Worker가 새 틱과 "이 포지션 청산됨" 표시를 **한 번의 원자적 커밋**으로 쓴다. 그래서 청산된 포지션을 나중에 반등한 가격으로 닫는 일이 불가능하다.
- 증거금은 진입 순간 금고로 들어간다(포지션은 금고에 대한 청구권). 그래서 강제 청산은 코인 이동이 없고, Worker가 표시만 하면 된다. 기록용 장부 줄은 플레이어 앱이 다음 접속 때 남긴다.

### 공정성 증명 (선택)
매일 0시에 Worker가 그날 난수 씨앗의 해시를 시세 문서에 공개하고, 다음 날 씨앗을 공개한다.
딜러 화면의 기록 감사(지금의 리플레이 감사)처럼, 지난 시세가 정말 씨앗과 공개된 사건만으로 만들어졌는지 누구나 다시 계산해 볼 수 있다.

### 무료 한도 계산 (Spark, Workers Free)
| 항목 | 하루 최대 | 한도 |
|---|---|---|
| 시세 쓰기 (15초 틱, 시간당 문서 1개에 갱신) | 5,760 | Firestore 쓰기 20,000 |
| 아무도 안 볼 때 (최근 2분 접속 신호 없음) | 1분 1회로 줄임 → 1,440 | |
| 시세 읽기 (화면을 연 사람마다 틱당 1) | 5명이 2시간씩 보면 약 2,400 | 읽기 50,000 |
| Worker 호출 | 크론 1,440 | 100,000 |

Worker 무료 요금제의 CPU 10ms 제한은 1단계에서 실제로 재 본다. 빠듯하면 틱 간격을 20초로 늘린다.

### 실제 코인 시세 연동 (선택 모드)
"실제 코인"을 말 그대로 원하면, Worker가 업비트 공개 시세(BTC, ETH 등)를 받아 FTN = BTC 변동률 × 3처럼 **증폭해서 섞는** 모드를 켤 수 있다.
- 장점: 진짜 시장이라 누구도 미래를 모른다. 진짜 차트를 아는 사람만의 재미.
- 단점: 해방 랠리 같은 세계관 사건을 덮어쓰고, 새벽에 실제 시장이 조용하면 판도 조용하다.
- 추천: 기본은 세계관 엔진, 이 모드는 종목별 스위치로 나중에.

## 5. 뉴스 — 각 구역의 목소리로

| 종목 | 형식 | 예시 |
|---|---|---|
| HBT | 탑의 시스템 창 | `[공지] 밸런스 패치가 적용되었습니다. HBT 변동성 1.5배 (1시간).` |
| LNH | 마왕성 서기관의 고시 | 임대료 납부일. 마왕성 꼭대기 창문에 밤새 불이 켜져 있다. |
| JWN | 운표가의 소문 | 천금표국 수레가 오늘은 전각 쪽으로만 올라간다. |
| S9 | 회장의 약관 | 서비스 약관 제14조 개정. 구독료가 사전 고지 없이 인상되었습니다. |
| ORB | 마더의 안내 방송 | 제3갑판 여러분, 잠깐 절약 모드로 바꿀게요. 조금 졸릴 거예요. |
| BLC | 부채 뒤의 귓속말 | 공작부인의 부채가 오늘 두 번 접혔다고 합니다. |
| MWL | 호텔 안내문 | 오늘 밤 하늘에 달이 보이면 암막 커튼을 치십시오. |
| WHL | 역 전광판 | 판돈로 인파 증가. 하우스 앞 줄이 광장까지 이어진다. |

- **딜러 뉴스 작성기**: 종목, 방향(↑/↓/모름), 세기(소·중·대), 지속(10분~6시간), 문구, "귓속말 예고(몇 분 전 흐린 소문)" 여부를 고른다. 발표 시각이 되면 Worker가 충격을 넣는다. 발표 전에는 플레이어가 읽을 수 없다.
- 본편 RP와 잇기: 디스코드에서 마왕과 대화가 있었다면, 딜러가 그 장면을 LNH 뉴스로 띄우면 된다.

## 6. 화면

### 시세판 (거래소 첫 화면) — 종점역 출발 안내판
포르투나는 기차역이 있는 종점 도시다. 시세판을 역의 **스플릿 플랩(넘김판) 출발 안내판**으로 만든다.
- 행마다 행선지 대신 종목: 티커, 이름, 현재가, 24시간 등락, 작은 꺾은선, 국면(평온/폭풍/해방).
- 틱마다 바뀐 숫자만 플랩이 착착 넘어간다. 소리는 플랩 딸깍 + 뉴스가 뜰 때 역 종소리(Web Audio 합성, 지금의 효과음 설정을 따른다).
- 맨 위에 다음 틱까지 남은 초를 도는 시계바늘로 표시.

### 종목 화면
- **차트**: 캔들 (1분·5분·15분·1시간). TradingView의 오픈소스 차트 라이브러리 `lightweight-charts`(Apache-2.0, 작고 실시간 갱신에 강함)를 쓴다.
- 차트 위에 사건 깃발: 해방, 뉴스, 밸런스 패치가 일어난 자리에 작은 표식.
- 새 틱이 오면 마지막 캔들이 자라고 현재가가 초록/빨강으로 잠깐 빛난다.
- **주문 패널**: 롱/숏, 증거금 칸(빠른 버튼 10·50·100·500·최대), 배율 칩, 그리고 계산된 값들: 명목가, 예상 청산가, 수수료, 시간당 이자.
- 확인 창은 "지배인 대출 약정서" 한 장. 빌리는 금액과 이자가 적혀 있고, 서명하면 접수 도장이 찍히며 포지션이 열린다. 1배는 빌린 돈이 없어 약정서 없이 바로 열린다.

### 내 포지션
- 카드마다 실시간 손익(%, 코인)이 카운터로 굴러가고, 청산가까지의 거리를 막대로 보여 준다. 위험 구간이면 테두리가 맥박처럼 뛴다.
- **강제 청산 연출**: 카드가 가장자리부터 타들어 간다. 이 도시에서 코인은 탄다.
- **수익 상한 익절**: 금빛 도장과 지금의 승리 색종이.
- 거래 기록은 지갑 탭의 장부에 그대로 섞여 보인다.

### 딜러 화면 (새 탭 "거래소")
- 종목 상태: 현재가, 국면, 열린 포지션 수, 지배인 금고의 최대 노출(최악의 경우 나갈 돈)
- 뉴스 작성기, 간부전 예고 버튼
- 서킷 브레이커: 종목 또는 전체 거래 일시 정지
- 설정: 수수료, 이자, 배율 한도, 증거금 한도, 하루 건수, 틱 간격, FTN 빚 연동 스위치
- 포지션 목록과 강제 무효(문제 생겼을 때 증거금 반환)

### 디스코드 알림 (지배인 말투 허용 구역)
- 큰 수익 익절, 강제 청산(기존 큰 승패 기준 1,000 이상), 구역 해방 랠리, 딜러 뉴스 발표.
- 예) 청산: "손님의 담보는 제가 잘 보관하겠습니다. 행운이 함께하기를."

## 7. 데이터 구조

| 경로 | 쓰는 쪽 | 내용 |
|---|---|---|
| `config/market` | 딜러 | 3절의 모든 계수, 한도, 스위치 |
| `market/h{시간번호}` | Worker | 그 시간의 1분 캔들 `m`(종목별 시고저종) + 최신 틱 `last {seq, at, p:{FTN:…}}`. 가격은 1/100 단위 정수 |
| `market/engine` | Worker만 읽고 씀 | 난수 상태, 국면, 앵커, 진행 중인 충격 |
| `marketNews/{id}` | 딜러 작성, Worker 발표 | 문구, 종목, 충격(발표 전 비공개), 발표 시각 |
| `positions/{pid}_{n}` | 플레이어(규칙 검증), Worker는 청산 표시만 | 종목, 방향, 배율, 증거금, 진입 틱·가격, 청산가, 상태(open/closed/liquidated), 종료 틱·가격, 지급액 |
| `oracles/{uid}` | 콘솔 | Worker 계정 허용 목록 |

장부 새 종류:
- `marketOpen`: 잔액 −(증거금 + 개설 수수료), 금고 +같은 금액
- `marketClose`: 잔액 +지급액, 금고 −지급액
- `marketLiquidated`: 잔액 변화 0. 기록용

지갑에 `open.market`(열린 포지션 수)과 하루 카운터 `trade`가 붙는다. 기존 한도 구조(`limitPeriod`)를 그대로 쓴다.

## 8. 구현 순서

1. **엔진** (`packages/core/src/market`): 시세 모델, 수수료·이자·청산 계산(규칙과 같은 정수 계산), 시뮬레이션으로 기대값 고정
2. **시세 기록원** (`apps/notifier`에 크론 추가): 전용 계정 로그인, 틱 쓰기, 원자적 청산 표시, 접속 신호에 따른 절전 — 먼저 CPU 한도 확인
3. **규칙과 데이터 계층**: 진입·청산·청산 기록, 규칙 테스트 (예전 설정 문서로도 통과하는지 포함)
4. **화면**: 시세판, 종목 차트, 주문, 포지션, 연출과 소리
5. **세계관 연결**: 해방·하우스 개장 자동 반영, 뉴스 작성기, 딜러 탭, 디스코드 알림, FTN 빚 연동
6. **e2e**: 에뮬레이터에서 가짜 기록원으로 틱을 밀어 넣고 진입·청산·강제 청산까지

사용자 손이 필요한 것: Worker용 계정 등록(관리자 등록과 같은 방식) 한 번, `wrangler deploy` 한 번.
