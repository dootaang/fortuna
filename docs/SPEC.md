# 포르투나 웹앱 설계서

디스코드 RP "종점도시 포르투나"의 보조 웹앱. 플레이어 약 5명, 캠페인 약 13주, 딜러(GM) 1명.
Firebase Spark(무료) 요금제: Authentication(익명 + Google), Firestore, Hosting. Cloud Functions 없음.

## 1. 구조

```
apps/fortuna      웹앱 (React 19, Vite, Tailwind 4, react-router)
  src/pages       플레이어 화면: 개찰구, 도착, 로비, 일터, 도박장, 상점, 지갑
  src/work        일 게임 4종 화면
  src/games       도박 테이블과 8종 화면
  src/dealer      /dealer 관리자 화면
apps/notifier     디스코드 중계 Cloudflare Worker
packages/core     순수 로직과 콘텐츠 (테스트: vitest, 환수율 시뮬레이션)
packages/data     Firestore 트랜잭션. 앱과 테스트가 같은 코드를 쓴다
packages/rules-tests  에뮬레이터에서 보안 규칙 + Worker 검증
e2e               Playwright: 휴대폰 플레이어 흐름, 데스크톱 딜러 흐름
```

## 2. 로그인

- **플레이어**: 익명 로그인 → 접속 코드 입력 → `bindings/{uid}` 생성. 규칙은 `accessCodes/{sha256(코드)}`와 대조한다.
  코드 원문은 `playerSecrets/{pid}`(관리자 전용)에만 있다. 같은 코드로 여러 기기를 연결할 수 있다.
- **재발급**: `players.codeVersion`이 올라가고, 모든 규칙이 `binding.version == player.codeVersion`을 확인하므로 예전 기기는 즉시 끊긴다.
- **딜러**: Google 로그인 + `admins/{uid}` 문서(콘솔에서만 생성, 클라이언트 쓰기 금지).

| 경로 | 쓰기 | 내용 |

| `shopItems/{id}`, `…/secret/body` | 딜러 / 재고만 장부 동반 | 품목, 비밀 본문(산 사람만 읽기) |

"장부 동반" = 같은 묶음에서 만들어진 장부(`lastLedger`)가 그 변경을 설명해야 한다.

## 4. 장부 규칙 (firestore.rules)

지갑 규칙은 "seq가 1 오르고, 그 번호의 장부가 이번 묶음에서 새로 생겼는가"만 본다.
장부 규칙이 지갑의 변경 후 상태 전체와 금고·재고·보유 물품의 변화를 종류별로 검증한다.

| 종류 | 검증 |
|---|---|
| arrival | 한 번만. 환영 봉투 − 개찰구 요금, 빚 기록, 개찰구 요금은 금고로 |
| work | 임금이 최저~최고 범위, 공제 = floor(임금 × 공제율), 해방 구역은 0, 공제는 금고로, 주간 횟수 |
| betOpen | 진행 중인 판 없음, 하우스 개방, 테이블 열림, 판돈 범위, 주간 판 수, 하우스는 판돈을 금고로 |
| betSettle | 진행 중인 판과 일치, 지급 ≤ 판돈 × 최대 배수, 하우스는 지급만큼 금고에서 |
| skill | 비용 = 누적표[사용 점수] − 누적표[기본 점수 − 1], 부족분만 빌릴 수 있고 빚 = 빌린 돈 + 수수료 |
| repay | 빚 이하, 금고로 |
| jointDeposit / fundContribution | 공동 지갑·모금함이 정확히 그만큼 늘어남, 모금함은 목표 초과 불가 |
| shop | 노출된 품목, 가격 일치, 재고 감소, 1인 한도, 보유 물품 증가 |
| itemUse | 소모품 1개 감소 (딜러는 아무 물품이나) |
| adminAdjust | 딜러만, 사유 메모 필수 |

주차는 `floor((서버시각ms + 9h − 4d) / 7d)` (KST 월요일 0시). 클라이언트는 시작할 때 서버 시각과의 차이를 재서 같은 값을 쓴다.

## 5. 봉인된 도박

1. **판 열기**: 판돈 차감과 함께 `openWager`가 서버 시각 `openedAt`과 그 순간의 테이블 파라미터를 기록한다.
2. **결정**: 플레이어의 결정 하나가 `openWager.steps.{n} = {a: 행동, t: 서버 시각}`으로 먼저 기록된다(규칙: 한 번에 정확히 하나, 시각은 request.time).
3. **결과**: n번째 난수는 `wagerId:n:t[n]`에서 만든다. 결정 전에는 결과를 알 수 없다.
4. **정산**: 앱이 기록을 재생해 지급액을 계산해 장부에 남긴다. 규칙은 상한만 검사하고, 딜러 화면의 "재생 검증"이 지급액이 정확한지 확인한다.
5. **이탈**: 기록이 서버에 있으므로 새로고침하거나 기기를 바꿔도 같은 판이 이어진다.

## 6. 게임과 기대 환수율 (기본값, `node packages/core/test/rtp-report.ts`)

| 게임 | 뒷골목 | 하우스 | 조정 파라미터 |
|---|---|---|---|
| 홀짝 | 100% (2배) | 95% (1.9배) | `payout` |
| 하이로우 | ≈100% | ≈95% | `multipliers` 5단계 |
| 스물하나 | ≈100% (블랙잭 2:1) | ≈95.5% (블랙잭 1:1, 소프트17 히트) | `naturalPayout`, `dealerHitsSoft17` |
| 막차 | 99% | 95% | `returnRate`, `factor`(1.2), `stations`(10) |
| 룰렛 | 100% (0 없음) | 94.7% (0, 00) | `zeros` |
| 주사위 포커 | ≈100% | ≈95% | `winPayout`, `tiesPush` |
| 도둑잡기 | ≈100% | ≈95% | `payout` |
| 포커(드로우) | ≈100% | ≈95% | `winPayout`, `tiesPush` |

딜러 화면 › 설정 › 테이블별 설정에서 게임마다 켜고 끄고, 파라미터를 JSON으로 바꿀 수 있다.

## 7. 일

틀 4종(분류·기억·셈·타이밍) × 구역 8곳의 겉모습. 성과 0~1이 임금 최저~최고에 대응한다(기본 150~250, 10 단위).
결과 화면은 "임금 / 지배인 몫 / 수령"을 보여 준다.

## 8. 디스코드

앱이 이벤트 문서를 만들고 Worker에 이벤트 id와 로그인 토큰을 보낸다. Worker는 그 토큰으로 Firestore REST를 읽으므로
보안 규칙이 그대로 적용되고(자기 이벤트만), 정해진 문구로만 게시하며, `sentAt`을 먼저 찍어 중복 게시를 막는다.
웹훅 주소는 Worker 비밀값에만 있다. 실패한 알림은 딜러 화면에서 다시 보낼 수 있다.

## 9. 남는 위험 (알고 감수하는 것)

- 일 게임 성과는 클라이언트가 정한다 → 주당 최대 `임금 최고 × 횟수`(기본 2,500)까지만 부풀릴 수 있다.
- 도박 정산 지급액을 위조하면 규칙은 상한(판돈 × 최대 배수)만 막는다 → 딜러의 재생 검증에서 반드시 드러난다.
- 개발자 도구로 이미 나온 카드·주사위를 보는 것은 의미 없다(다음 난수는 결정 후에 정해진다).

## 10. 나중: 플레이어 간 실시간 대전

모든 게임은 "상태 + 행동 → 새 상태"의 순수 함수이고, 행동은 서버 시각으로 봉인된다.
대전은 `tables/{id}` 문서에 좌석과 `steps`를 두고 같은 방식으로 각 좌석이 차례대로 행동을 봉인하면,
모든 참가자가 같은 기록을 재생해 같은 판을 본다. 정산은 테이블 단위 장부 묶음으로 확장한다.
