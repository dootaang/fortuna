# PvP 도둑잡기 설계 (초안)

플레이어 2~4명이 공개 방을 열고 들어와 코인을 걸고 겨루는 도둑잡기.
서버(Cloud Functions) 없이 Firestore 보안 규칙만으로 공정성을 지키고, 연출은 lucky-arcade 도둑잡기에서 이식한다.

## 1. 규칙

- **인원**: 2~4명. 방장이 최대 인원을 정한다.
- **덱**: 같은 숫자 두 장(하트와 스페이드)으로 이루어진 짝들에 조커 1장을 더한다. 인원이 적으면 판이 너무 길어지지 않게 짝 수를 줄인다.

  | 인원 | 짝 | 총 장수 |
  |---|---|---|
  | 2명 | 10짝 | 21장 |
  | 3명 | 12짝 | 25장 |
  | 4명 | 13짝 | 27장 |

- **배분과 첫 버림**: 좌석 순서대로 한 장씩 나눈다. 처음 받은 패 안의 짝은 자동으로 버린다.
- **차례**: 내 차례가 되면, 카드가 남아 있는 다음 좌석(제시자)의 패에서 한 장을 뽑는다. 짝이 맞으면 자동으로 버린다. 그다음 차례는 방금 뽑힌 사람에게 넘어간다.
- **제시 단계** (lucky-arcade SPEC-A18 방식): 뽑히기 직전에 제시자는 아래 두 가지를 할 수 있다.
  - **재배열**: 자기 패 순서를 최대 3회 바꾼다. 다른 사람에게는 보이지 않는다.
  - **내밀기**: 한 장을 살짝 들어 올린다. 모두에게 보이는 블러핑이다.
- **눈치 신호**: 뽑는 사람이 손가락을 올려 둔 위치가 제시자 화면에 실시간으로 표시된다. NPC 표정 대신 사람끼리의 심리전이다.
- **종료**: 패를 다 턴 순서가 기록되고, 마지막까지 조커를 든 사람이 진다.

## 2. 숨길 정보와 공개할 정보

도둑잡기에서 실제로 의미 있는 비밀은 **"내 패에서 조커가 몇 번째에 있는가"** 하나다.
뽑는 사람이 고를 수 있는 것은 위치뿐이다. 그래서 위치(순서)만 철저히 숨기면, 누가 어떤 카드를 가졌는지가 알려져도 유리한 선택을 할 수 없다.

| 정보 | 저장 위치 | 볼 수 있는 사람 |
|---|---|---|
| 좌석별 카드 **묶음** (정렬된 목록) | `pvpRooms/{id}` 공개 문서 | 방 참가자. 화면에는 장수만 표시 |
| 좌석별 카드 **순서** | `pvpRooms/{id}/hands/{uid}` | **본인만** (보안 규칙으로 막음) |
| 버린 짝, 마지막 조커 | 공개 문서 | 모두 |

- 묶음을 공개하는 이유는 신뢰할 딜러 없이 공정하게 나누기 위해서다(3절).
- 공개되는 것은 데이터일 뿐이고, 화면은 상대 패를 뒷면으로만 보여 준다.

## 3. 공정성 (서버 없이)

### 배분
1. 방장이 "시작"을 누르면 서버 시각 `startedAt`이 봉인된다.
2. 덱 순서는 `seed = 방ID:startedAt`으로 정해지고, 다음 쓰기에서 좌석별 묶음이 기록된다. 이 쓰기는 누가 해도 된다.
3. 모든 참가자의 앱이 같은 시드로 직접 다시 계산해 기록과 대조한다. 다르면 누구든 "무효"를 선언할 수 있고, 판은 취소되어 판돈이 전액 환불된다.

방장이 결과를 미리 알고 골라서 기록할 수 없다. 시각이 봉인된 뒤에야 덱이 정해지기 때문이다. 바꿔치기를 하면 모든 앱이 바로 알아챈다.

### 뽑기
1. 뽑는 사람이 "i번째 카드"를 기록한다. 서버 시각이 함께 찍힌다.
2. 제시자의 앱이 자기 순서 문서에서 i번째 카드를 꺼내 옮긴다.
   - 보안 규칙은 비공개 순서 문서를 직접 읽어서, 옮긴 카드가 정말 i번째인지 검사한다(규칙의 `get()`은 읽기 권한과 무관하게 읽을 수 있다).
   - 짝 여부도 규칙이 직접 계산한다: 하트↔스페이드 + 같은 숫자.
3. **제시자가 응답하지 않으면**(8초): 누구든 대신 처리할 수 있다. 이때 카드는 `공개 묶음[뽑은 시각 % 장수]`로 정해지고, 규칙이 이 공식을 그대로 검사한다.
4. **뽑는 사람이 시간을 넘기면**(20초): 누구든 대신 뽑을 수 있다. 위치는 서버 시각으로 정해진다.

그래서 한 명이 접속을 끊어도 판은 끝까지 진행된다.

## 4. 판돈과 정산

| 단계 | 장부 | 내용 |
|---|---|---|
| 방 만들기 / 들어가기 | `pvpStake` | 지갑에서 판돈 S를 방 금고로 옮긴다. 하루 도박 횟수 1회 차감. 동시에 한 방만 가능 |
| 시작 전 나가기 | `pvpRefund` | S를 돌려받는다 |
| 끝 | `pvpPayout` | 각자 자기 몫을 청구한다. 규칙이 방의 최종 상태로 금액을 검산하고, 두 번 청구는 막는다 |
| 무효 | `pvpRefund` | 전원에게 S를 돌려준다 |

**분배 (기본안: 패자 독박)**
- 판 전체 금액은 P = S × 인원이다.
- 수수료는 판 전체 금액 × 수수료율이고, 지배인 금고로 들어간다. 뒷골목은 0%, 하우스는 5%를 제안한다.
- 승자 각자의 몫은 ⌊(P − 수수료) / (인원 − 1)⌋이다. 패자는 0이다. 나눗셈에서 남는 1~2코인은 금고로 간다.
- 예시:
  - 4명, 판돈 100: 패자 −100, 승자 셋 각 +33
  - 2명: 이긴 사람이 상대 판돈을 통째로 가져간다

**선택안 (순위 차등)**: 패자의 판돈을 먼저 턴 순서대로 3:2:1로 나눈다.

**정산 시점**: 앱을 열면 끝난 방의 몫을 자동으로 청구한다. 판이 끝난 직후 나가 버린 사람도 결국 받는다.

**딜러 화면**: 진행 중인 방 목록을 보고 강제로 무효 처리할 수 있다(전원 환불, 사유 기록).

## 5. 데이터 구조

```ts
pvpRooms/{roomId} {
  game: "old-maid", venue: "alley" | "house", stake, maxSeats, rakeBps,
  status: "waiting" | "dealing" | "playing" | "finished" | "void",
  hostUid, createdAt, startedAt, seed,
  seats: [{ uid, playerId, name, joinedAt, lastSeen, emote: { kind, at } | null }],
  sets: { [seat]: CardId[] },          // 공개 묶음 (화면에는 장수만)
  discards: { card: CardId, by: seat }[],
  turn: { actor, target, since, offerReady, raised: number | null, reorders, hover: number | null,
          pick: { index, at, auto: boolean } | null },
  lastMove: { actor, target, card: CardId | null, paired: boolean, at } | null,   // 짝이 아니면 card는 비움
  finishOrder: seat[], loser: seat | null,
  claimed: { [seat]: boolean }, version
}
pvpRooms/{roomId}/hands/{uid} { order: CardId[] }    // 본인만 읽기·쓰기. 공개 묶음의 순열이어야 함
wallets/{pid}.room: roomId | null                     // 한 번에 한 방
ledger: pvpStake / pvpRefund / pvpPayout              // 기존 장부 규칙에 종류 추가
```

**규칙이 검사하는 전환**
- 들어가기·나가기
- 시작
- 배분 기록 (형식만 검사하고, 내용은 모든 앱이 대조)
- 내밀기·재배열 횟수
- 뽑기 지정 (차례, 시간)
- 뽑기 처리 (i번째 카드, 짝 계산, 다 턴 사람 처리, 다음 차례)
- 시간 초과 대행
- 정산 청구 (금액 공식)
- 무효

## 6. 화면과 연출 (lucky-arcade에서 이식)

| 요소 | 이식 방법 |
|---|---|
| 배분 (덱에서 좌석으로, 장당 82ms 간격, 430ms) | `DealingAnimation`. 좌석 ID만 일반화 |
| 뽑기: 집기 → 뒤집기 → 손으로 회수 (620 / 960 / 1480ms) | `DrawReveal`, `flightTransform`, `captureDrawOrigin`. 내가 뽑거나 뽑힐 때는 가운데에서 뒤집고, 남끼리는 바로 날아가게 |
| 제시 단계, 재배열 FLIP (600ms) | `OfferStage`, `useHandFlip`, `offer-timing` |
| 짝 버리기, 버림 더미 착지 (560ms, 좌석 방향 오프셋과 흔들림) | `DiscardStage`(자동 모드), `DiscardPile`, `pileOffset` |
| 차례 표시, 버튼 눌림, 3D 뒤집기 CSS | old-maid.css에서 해당 블록만 |
| 승패 | 우리 `celebrate`와 `Counter`. 조커가 공개될 때 흔들림과 붉은 섬광을 추가 |

- **좌석 배치**: 나를 항상 아래에 둔다. 2명이면 상대는 위, 3명이면 좌우, 4명이면 좌·위·우.
- **카드 그림**: 테메로세 그림 대신 우리 벡터 카드와 아르데코 뒷면을 쓴다.
- **원격 연출**: 남의 행동은 방 문서가 바뀔 때마다 `lastMove`를 연출 대기열에 넣어 순서대로 재생한다. 스냅샷이 몰려와도 연출이 겹치지 않는다.
- **입력**:
  - 두 번 탭해서 뽑는다(첫 탭은 집기).
  - 재배열은 길게 눌러 집고 탭해서 옮긴다. 터치와 마우스 모두 지원한다.
  - 원본에서 발견된 롱프레스 직후 선택이 풀리는 버그 후보는 고쳐서 이식한다.
- **반응 이모트**: 😏 😰 😂 🙏를 좌석 위에 띄운다. 1.5초에 한 번까지.
- **버리는 것**: NPC 로직, 대사·초상, 관전 속도 조절, 일시정지, 테메로세 연결 코드 전부.

**도박장 화면**
"모두의 판" 칸에 대기 중인 방 목록을 보여 준다(방장, 판돈, 인원, 장소). [방 만들기]에서는 판돈, 인원, 뒷골목·하우스를 고른다.

**디스코드 알림**
- "에이든 님이 뒷골목에 도둑잡기 판을 열었습니다 · 판돈 100 · 1/4"
- 판이 끝나면: "벨라 님이 조커를 떠안았습니다"

## 7. 구현 순서

1. **순수 엔진** (`packages/core`): 가변 좌석, 배분, 짝 계산, 차례, 다 턴 사람 처리, 정산 공식. 단위 테스트 포함.
2. **보안 규칙과 데이터 계층**: 방 만들기, 들어가기, 나가기, 시작, 배분, 제시, 뽑기, 처리, 시간 초과, 정산, 무효. 에뮬레이터 테스트 포함.
3. **방 목록과 기본 화면** (연출 없이). 브라우저 2~4개를 동시에 띄우는 e2e.
4. **연출 이식**: 배분, 뽑기, 제시·재배열, 버리기, 승패, 이모트.
5. **디스코드 알림, 딜러 화면** (방 감시, 강제 무효), 마무리.

## 8. 정해야 할 것 (괄호는 추천)

1. 분배 방식: 패자 독박 / 순위 차등 (패자 독박)
2. 수수료: 뒷골목 0% · 하우스 5% / 둘 다 0% (뒷골목 0% · 하우스 5%)
3. 하루 도박 횟수 차감: 참가 1회 차감 / 차감 안 함 (1회 차감)
4. 눈치 신호(뽑는 사람의 손가락 위치 공유): 켜기 / 끄기 (켜기)
5. 시간 제한: 차례 20초, 제시자 응답 8초, 제시(재배열) 12초 (이대로)
6. 관전: 나중에 (나중에)
